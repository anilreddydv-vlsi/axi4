A master and a slave, joined by five one-way channels

The master starts every transaction (a CPU or DMA). The slave answers (a memory or peripheral). Writes use three channels, reads use two, and each channel only carries information in one direction.

A write is like posting a parcel

You write the address label (AW), send the contents in one or more boxes (W), and get a single delivery receipt back (B).

A read is like ordering by mail

You send a request slip with the address (AR), and the goods come back in boxes, each with a note saying all is well or not (R).

Why separate channels?

Reads and writes never block each other, and a master can send new addresses while older data is still moving. That is where AXI's speed comes from.

The handshake: VALID meets READY

Every channel uses the same two wires. The sender raises VALID when it has something. The receiver raises READY when it can take it. Information moves on the rising clock edge where both are high. Click any cell to flip VALID or READY, or load a pattern.

Four words that get mixed up

For the interactive version see burst types, section 2

Transfer

One VALID/READY handshake on any channel. The address, each data piece and the write response are all transfers.

Beat

One data transfer inside a burst. A beat is a transfer; the address and response are not beats.

Burst

All the beats produced from one start address. AxLEN + 1 beats long.

Transaction

The whole job: address + all beats + (for writes) the response. A 4-beat write = 1 + 4 + 1 = 6 transfers.

Bursts: send one address, move many beats

The master sends only the first address. Three fields tell the slave how to work out the rest: AxLEN = beats − 1, AxSIZE = bytes per beat as a power of two, and AxBURST = how the address moves. Here are 4 beats of 4 bytes starting at 0x38:

FIXED 2'b00

0x380x380x380x38

Same address every time. For a FIFO register. Up to 16 beats.

INCR 2'b01

0x380x3C0x400x44

Goes up by the beat size. For memory. 1 to 256 beats; must not cross a 4 KB boundary.

WRAP 2'b10

0x380x3C0x300x34

Goes up, then wraps inside a 16-byte window (0x30–0x3F). For cache lines. 2, 4, 8 or 16 beats.

Try every combination in the burst simulator and the 4 KB boundary explorer.

Every transaction gets an answer

A write gets one response on B, after the last beat. A read gets a response on every R beat. A burst always runs to its full length, even after an error.

OKAY 2'b00

Normal success. Also the answer when an exclusive access fails.

EXOKAY 2'b01

An exclusive access succeeded.

SLVERR 2'b10

The slave got the request but could not do it, such as a write to a read-only register.

DECERR 2'b11

No slave lives at that address. Usually sent by the interconnect.

IDs let fast answers overtake slow ones

The master sends read A to slow DRAM, then read B to fast on-chip SRAM. Whether B may finish first depends only on their IDs: same ID must stay in order, different IDs may finish in any order.

Rules to remember

Reset quietly

While ARESETn is low, the master drives ARVALID, AWVALID and WVALID low and the slave drives RVALID and BVALID low. VALID may rise only on a clock edge after reset is released.

Never wait for READY

A sender must not wait for READY before raising VALID. A receiver may wait for VALID before raising READY. This stops the two sides deadlocking.

Hold until accepted

Once VALID is high, it and the information must stay unchanged until the handshake completes.

Read data after the address

The slave must see ARVALID and ARREADY both high before it raises RVALID.

Write response after everything

BVALID only after the last W beat (WLAST) and, in AXI4, the AW address have both been accepted. W data may arrive before AW.

No early stop, no 4 KB crossing

A burst always completes all AxLEN + 1 beats. An INCR burst must stay inside one 4 KB page.
