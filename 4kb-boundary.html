The AXI 4 KB boundary rule

Memory is cut into 4 KB pages: 0x0000–0x0FFF, 0x1000–0x1FFF and so on. An AXI burst must start and end inside the same page. Set a burst below and drag it toward 0x1000 to see what goes wrong.

What the 4 KB boundary is

4 KB is 4096 bytes, or 0x1000. A 4 KB boundary is any address whose low 12 bits are zero: 0x0000, 0x1000, 0x2000, 0xABC000. The bytes between two boundaries form one 4 KB page. The rule says no burst may cross from one page into the next: every byte it touches must share the same upper address bits, AxADDR[31:12].

The slave, not the master, computes the addresses after the first beat. AXI therefore needs a guarantee that those addresses stay where the first one was decoded.

1. Decode happens once

The interconnect looks only at AxADDR to pick a slave, then sends the whole burst there. The smallest address region a slave is given is 4 KB. If a burst crossed, its later beats would go to the slave that owns the start address, not the one that owns the bytes.

2. Simpler slaves

Because a burst never crosses, a slave's address incrementer only has to handle the low 12 bits; the upper bits stay fixed for the whole burst. Interconnect and slave logic both get smaller and faster.

3. Pages match the MMU

Often taught as well: 4 KB is the smallest page size in most MMUs. Two neighbouring pages can map to different physical memory or have different permissions and attributes. A burst staying in one page keeps one translation and one set of attributes.

Which bursts can cross

BurstCan it cross?Why
INCRYes, and that's illegal, so the master must prevent itUp to 256 beats of 128 bytes is 32 KB. Any INCR whose end runs past the next 0x…000 address crosses
WRAPNeverThe window is at most 16 beats × 128 bytes = 2 KB and starts at a multiple of its own size, so it always sits inside one page
FIXEDNeverEvery beat uses the same address, and one beat is at most 128 bytes aligned to its size

For an INCR, the biggest legal burst from a given start is the bytes left in the page: 0x1000 − AxADDR[11:0]. Starting at 0x0F00 leaves 0x100 = 256 bytes, so 64 beats of 4 bytes or 16 beats of 16 bytes, and no more.

Check yourself

DV corner: assert it, constrain it, test the edges

Assertion on the AW channel (same for AR)

// Last byte of an INCR burst stays in the start page
logic [ADDR_W-1:0] aw_aligned, aw_last;
assign aw_aligned = awaddr & ~((ADDR_W'(1) << awsize) - 1);
assign aw_last    = aw_aligned + ((awlen + 1) << awsize) - 1;

a_aw_4kb: assert property (@(posedge aclk) disable iff (!aresetn)
  (awvalid && awburst == 2'b01) |->
    aw_last[ADDR_W-1:12] == awaddr[ADDR_W-1:12])
  else `uvm_error("AXI4KB", $sformatf(
    "INCR from 0x%0h to 0x%0h crosses 4KB", awaddr, aw_last))

Constraint in the sequence item

// Keep random INCR bursts legal
constraint c_4kb {
  (burst == INCR) ->
    ((addr & ~((1 << size) - 1)) % 4096)
      + ((len + 1) << size) <= 4096;
}
// For negative tests, turn it off:
//   item.c_4kb.constraint_mode(0);

Edge cases to cover

A burst that ends exactly on the last byte of a page (legal), one that crosses by one beat, unaligned INCR starts near 0x…FFF, every AxSIZE at the page end, 256-beat bursts, and WRAP and FIXED bursts placed at 0x…FF0 to prove they never fire the check.
